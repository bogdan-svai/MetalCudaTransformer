# SOFTWARE REQUIREMENTS SPECIFICATION (SRS)
# SYSTEM LAYER: STAGE 3 - AUTOMATIC & MANUAL THREAD COARSENING OPTIMIZER
# -----------------------------------------------------------------------------

## 1. MODULE OVERVIEW & ARCHITECTURAL OBJECTIVES
The primary objective of Stage 3 is to implement a thread-coarsening and geometric transformation layer within the transpiler. This layer reduces physical Metal thread density while preserving the logical CUDA thread coordinates observed by kernel code.

The optimizer must support two discrete operational modes:
1. AUTO-COARSENING: Build-time recovery for statically known blocks exceeding the 1024-thread threadgroup ceiling.
2. MANUAL OVERRIDE: User-defined compiler flag parameters allowing deliberate coarsening loops for spatial cache optimization.

The Stage 1 `check` command remains strict and reports the original hardware violation. Recovery is available only through the Stage 3 `build` path.

## 2. PIPELINE EXTENSION

  [Validated Metadata] ---> Coarsening Planner ---> MSL Body Transformation
                                               ---> Physical Geometry Metadata
                                               ---> Routing Table

The planner operates on the X axis. The number of threadgroups remains unchanged; the physical `threads_per_threadgroup.x` value is divided by the coarsening factor. Stage 4 must consume the physical block dimensions from the routing table when dispatching Metal work.

## 3. DETAILED FUNCTIONAL REQUIREMENTS

### 3.1 CLI Flag Extensions
* REQ-3.1.1: Explicit Coarsening Parameter
  The `build` sub-command must evaluate `--coarsening <INT>`. Supported values are `[1, 2, 4, 8]`. Factor 1 disables coarsening. When omitted, automatic recovery may select 2, 4, or 8 for oversized static blocks.

### 3.2 Coarsening Computation & Code Generation
* REQ-3.2.1: Automatic Fallback Resolution
  If a launch registers a static block volume greater than 1024 and no manual factor is passed, the engine must select the smallest supported factor $F$ such that:
  $$\frac{DimX \times DimY \times DimZ}{F} \le 1024$$
  The factor must divide `DimX` exactly. If no supported factor satisfies both conditions, build must retain `HardwareLimitExceeded` and abort.

* REQ-3.2.2: Loop Unrolling Mutation
  For $F > 1$, the transpiler must execute the original kernel body once per logical X lane:

```metal
for (uint mcu_step = 0; mcu_step < F; ++mcu_step) {
    uint3 mcu_thread_idx = uint3(
        thread_position_in_threadgroup.x + mcu_step * threads_per_threadgroup.x,
        thread_position_in_threadgroup.y,
        thread_position_in_threadgroup.z
    );
    uint3 mcu_block_dim = uint3(
        threads_per_threadgroup.x * F,
        threads_per_threadgroup.y,
        threads_per_threadgroup.z
    );
    // Original body using mcu_thread_idx and mcu_block_dim.
}
```

  `threadIdx` must map to `mcu_thread_idx`, while `blockDim` must map to `mcu_block_dim`. This preserves CUDA indexing without ad-hoc mutation of individual array expressions.

* REQ-3.2.3: Kernel/Launch Consistency
  A kernel may only receive one coarsening plan per build artifact. If multiple launches of the same kernel require incompatible static block dimensions or factors, build must abort with `IncompatibleCoarseningPlan`.

### 3.3 Routing Table Schema Updates
* REQ-3.3.1: Optimization Vector Tracking
  `routing_table.txt` must include `optimization_metrics` for every kernel:

```json
{
  "mode": "none|manual|auto",
  "axis": "x",
  "coarsening_factor": 2,
  "original_block": [2048, 1, 1],
  "physical_block": [1024, 1, 1]
}
```

## 4. FAILURE AND EXIT POLICY

* Invalid CLI factors must be rejected by argument parsing with Exit Code 2.
* Dynamic or unresolved oversized blocks cannot be auto-coarsened.
* Manual coarsening requires a static X dimension divisible by the selected factor.
* Non-hardware Stage 1 errors remain fatal and cannot be suppressed by optimization.

## 5. TESTING AND ACCEPTANCE

`tests/test_stage3_coarsening.py` must cover:

* factor 1 preserving Stage 2 output;
* manual factors 2, 4, and 8;
* automatic recovery for 2048 and 4096 logical threads;
* invalid and non-divisible factors;
* routing-table physical geometry;
* mathematical uniqueness and completeness of logical X indices;
* native MSL syntax compilation on macOS through the verification script.

# SOFTWARE REQUIREMENTS SPECIFICATION (SRS)
# SYSTEM LAYER: STAGE 8 - CUDA MEMORY MODEL, ATOMICS & SYNCHRONIZATION
# -----------------------------------------------------------------------------

## 1. CURRENT BASELINE
Stage 7 is complete. MCU exposes global `compile`, `run`, and `make` commands,
links versioned MCU objects, loads offline `.metallib` artifacts, and caches host,
runtime, Metal, and final-link outputs.

Measured Stage 7 baseline on 2026-06-23:
* 41 tests pass in 9.35-10.70 s;
* MCU object compile: 0.19-0.20 s internal, 0.24-0.25 s wall;
* clean small native link: 1.67-1.70 s internal, 1.72-1.75 s wall;
* unchanged object link: 0.006 s internal, 0.05 s wall;
* new-process Metal initialization plus a small workload: 0.22-0.25 s;
* normal runtime performs zero MSL source compilations.

The assignment-scale CUDA probe now resolves its real project headers when run
from `gpu_miner` with:

  mcu compile ../common/miner.cpp src/sha256.cu src/utils.cu \
      -I../include -O2 -o miner_mcu

It reaches Metal compilation and exposes the concrete gaps listed below.

## 2. OBJECTIVE AND SCOPE
Stage 8 completes the CUDA memory semantics required by reductions, SHA-256,
Merkle construction, and concurrent nonce selection. It also closes semantic and
code-generation defects revealed by the first real project probe.

Stage 8 includes:
* array-parameter decay and complete reachable device call graphs;
* expression-level pointer address spaces and safe casts;
* private fixed arrays and byte-oriented helper operations;
* typed device/threadgroup atomics;
* static and validated dynamic threadgroup memory;
* uniform threadgroup barriers;
* synchronous runtime memset/copy behavior required by supported projects;
* compile/run tests for the Merkle and nonce kernels.

Stage 8 excludes:
* full assignment input/output equivalence, which is the Stage 9 gate;
* asynchronous streams and events, which belong to Stage 10;
* floating-point atomics without equivalent target semantics;
* warp intrinsics, cooperative groups, texture/surface memory, and arbitrary
  placement-new or C++ aliasing behavior.

## 3. OBSERVED FAILURES TO CLOSE

### 3.1 Invocation and build-system failures
* The project has no root `main.cu`; its host entry is `../common/miner.cpp`.
  Diagnostics and documentation must not suggest a nonexistent entry file.
* The project include path is `../include`, not `include`.
* Existing Make linking passes `-lm`; the validated NVCC driver must accept
  supported `-l<name>` and `-L<path>` link options and forward them safely.
* Users must not define CUDA qualifiers manually. MCU owns `__global__`,
  `__device__`, and `__host__` frontend semantics.

### 3.2 Semantic and MSL generation failures
* CUDA function parameters such as `const BYTE data[]` currently become invalid
  MSL `const uchar[] data`; parameter arrays must decay to typed pointers.
* Reachability misses calls including `d_strlen`, `sha256_update`, `intToString`,
  `memset`, and `atomicMin`, leaving source names in generated MSL.
* C-style pointer casts currently erase `thread`, `device`, or `threadgroup`
  qualifiers and produce illegal generic MSL pointers.
* The existing device `memset` registry entry is not selected when semantic call
  recovery misses the call, and its prelude supports only thread pointers.
* Parser diagnostics can contain Clang errors while presentation labels them as
  informational; severity and build-blocking policy must remain consistent.

### 3.3 Missing Stage 8 primitives
* `atomicMin` has no typed registry/lowering or atomic binding representation.
* Plain reads through a CUDA pointer also used atomically need legal MSL atomic
  load semantics.
* `__shared__` declarations have no typed IR, storage plan, or runtime binding.
* Divergent barrier detection is warning-only and is not based on a validated
  uniformity contract.
* Dynamic shared-memory byte counts are not propagated from launch to dispatch.

Storage decisions must be explicit before text emission. Regex replacement may
format an already validated expression, but it must not decide pointer address

## 5. COMPONENT OWNERSHIP
Suggested boundaries:
* `core/ir/memory.py`: storage classes, pointer/reference types, array extents;
* `core/ir/expressions.py`: casts, dereferences, pointer offsets, atomic accesses;
* `core/passes/call_recovery.py`: AST-backed complete call-edge recovery;
* `core/passes/address_spaces.py`: expression and helper specialization;
* `core/passes/atomics.py`: atomic-use analysis and typed lowering plans;
* `core/passes/threadgroup.py`: static/dynamic shared-memory layout;
* `core/passes/uniformity.py`: conservative barrier participation analysis;
* `core/backends/device.py`: emission from validated typed plans only;
* `core/registry/catalog.py`: signatures/capabilities, not ad-hoc body rewrites;
* `runtime/src/kernel_dispatcher.mm`: threadgroup byte binding;
* `runtime/src/buffer_registry.mm`: host memset and validated copy operations.

The device linker coordinates these passes but must not own their parsing or MSL
formatting logic.

## 6. MILESTONE 8A - COMPILER CORRECTNESS REPAIRS

### 6.1 Parameter arrays
In function parameters only, CUDA/C arrays decay to pointers:
* `BYTE data[]` -> pointer to mutable BYTE;
* `const BYTE data[]` -> pointer to const BYTE;
* `BYTE data[64]` -> pointer parameter, not a by-value MSL array.

Struct fields and local declarations retain fixed-array semantics. Canonical
symbol identity must normalize equivalent pointer/array parameter declarations so
declarations and definitions resolve to one function.

### 6.2 Complete call graph
Every syntactic call in reachable device code must become exactly one of:
* resolved user device function;
* resolved translation-registry intrinsic;
* recognized type construction/operator with no call edge;
* source-mapped unsupported or missing-device diagnostic.

If libclang omits a call because another unsupported CUDA symbol poisoned part of
the AST, a token-aware body recovery pass may recover candidate calls. Recovered
calls must still be resolved against semantic symbols/signatures. Blind global
replacement is forbidden.

The SHA fixture must resolve and rewrite at least:
* `d_strlen`, `sha256_init`, `sha256_update`, `sha256_final`;
* `sha256_transform`, `intToString`, `d_strcpy`, and `d_strcat`;
* `memset` and supported atomic calls.

### 6.3 Pointer casts and address spaces
Address space is attached to the pointee expression, not reconstructed from text.
Supported casts preserve the source storage class unless an explicitly validated
conversion exists. Examples:
* thread BYTE array -> `thread char*` view;
* device BYTE pointer -> `device char*` view;
* threadgroup T pointer -> compatible threadgroup byte view.

Cross-address-space casts are errors. C-style casts, `reinterpret_cast`, pointer
offsets, dereferences, struct-array fields, and helper arguments receive focused
tests.

### 6.4 Driver compatibility repair
Add validated link-only `-l`, `-L`, and required framework-independent native
link options. Compile-mode use of link-only flags is rejected or retained for the
final link according to NVCC behavior. `mcu make compile` must execute the
assignment Makefile locally without modifying it.

### 6.5 Acceptance for 8A
* The real SHA/Merkle source set reaches code generation with no unknown `BYTE`,
  `WORD`, `SHA256_CTX`, or `SHA256_HASH_SIZE` diagnostics.
* Generated helper signatures contain no array parameter syntax.
* Every reachable source call is rewritten or diagnosed before Metal compilation.
* Generated MSL contains no unqualified pointer cast.
* `mcu make compile` passes the assignment's compile and native-link arguments.

## 7. MILESTONE 8B - PRIVATE ARRAYS, BYTE OPERATIONS & MEMSET
Support:
* compile-time-sized thread-local arrays from literals, enums, and expression
  macros whose operands are compile-time constants;
* arrays inside plain structs and pointer access to those fields;
* byte indexing, pointer arithmetic, null terminators, and supported char/uchar
  views without losing address space;
* address-space-specialized device memset for thread, device, and threadgroup
  destinations where sequential byte-fill semantics are valid;
* fixed local constant tables such as SHA-256 round constants.

Variable-length private arrays remain unsupported and produce
`UnsupportedVariableLengthArray`. A macro expression accepted as fixed-size must
be evaluated/validated before MSL emission.

Device `memset` lowering must preserve the CUDA return value and byte count. Host
`cudaMemset` is implemented separately in milestone 8F.

Acceptance:
* standard SHA-256 vectors execute exactly through the original helper style;
* `SHA256_CTX::data`, schedule arrays, local hash buffers, and constant tables
  compile without source rewrites;
* thread/device byte casts and memset have source-mapped negative tests;
* no generic/unqualified pointer appears in generated MSL.

## 8. MILESTONE 8C - TYPED ATOMICS

### 8.1 Initial supported operations
* `atomicAdd`, `atomicCAS`, `atomicMin`, `atomicMax`, and `atomicExch`;
* signed and unsigned 32-bit integer forms where Metal semantics match;
* device and threadgroup pointer address spaces;
* CUDA-compatible return of the value observed before the operation.

64-bit and floating-point forms are rejected unless the selected Apple GPU and
Metal language version provide equivalent behavior and dedicated tests.

### 8.2 Atomic-use analysis
A pointer used atomically must receive an atomic pointee representation in MSL.
The pass records:
* operation and canonical value type;
* pointer address space;
* source call and target memory order;
* plain reads/writes through the same CUDA pointer.

For the nonce winner, CUDA `atomicMin(best_nonce, nonce)` becomes a typed Metal
atomic fetch-min. The preceding `*best_nonce` read becomes a legal atomic load;
it must not remain a plain dereference of `atomic_uint`.

Initial atomic operations use the weakest Metal ordering that preserves the CUDA
fixture's required atomicity. Ordering choices are explicit in the lowering plan
and documented; they are not implicit backend defaults.

### 8.3 Acceptance for 8C
* 20,000 logical threads increment one 32-bit counter with no lost updates;
* signed/unsigned min/max edge cases match CPU references;
* CAS and exchange return their previous values correctly;
* repeated nonce-winner runs return the smallest valid nonce, not merely the
  first physically scheduled thread;
* unsupported type/address-space combinations fail at the CUDA call site.

## 9. MILESTONE 8D - THREADGROUP MEMORY

### 9.1 Static shared memory
Static declarations such as `__shared__ float tile[256]` become deterministic
threadgroup storage with validated element type, extent, size, and alignment.
Static storage may be emitted as kernel-local MSL threadgroup arrays when no
runtime length is required.

### 9.2 Dynamic shared memory
Validated declarations such as `extern __shared__ BYTE scratch[]` become explicit
MSL threadgroup parameters. Launch shared-byte expressions are carried through
host transformation, routing metadata, and `setThreadgroupMemoryLength`.

Each dynamic descriptor contains:
* argument/slot index;
* source declaration and element type;
* alignment and launch byte expression;
* minimum/maximum validated size when statically derivable.

### 9.3 Coarsening interaction
Kernels using threadgroup storage or barriers are not coarsened until a dedicated
proof preserves one logical CUDA participant per synchronization participant.
Automatic/manual coarsening requests for such kernels produce a clear diagnostic
rather than silently changing shared-memory semantics.

### 9.4 Acceptance for 8D
* static shared-memory reduction matches CPU for odd and non-power-of-two counts;
* dynamic shared memory is bound at the expected slot and size;
* undersized, misaligned, and hardware-limit-exceeding launches fail before GPU
  execution;
* multiple kernels cannot collide in shared-memory descriptor ownership.

## 10. MILESTONE 8E - BARRIERS & UNIFORMITY
`__syncthreads()` lowers to a Metal threadgroup barrier with threadgroup-memory
visibility. The uniformity pass conservatively validates that every physical
thread in the threadgroup reaches barriers in the same order.

Required policy:
* unconditional barriers are supported;
* barriers under conditions proven uniform for the entire threadgroup may pass;
* conditions depending on thread-local IDs or divergent data are errors;
* early return before a later barrier is rejected unless proven uniform;
* barriers inside unsupported loops/switches fail safely.

`DivergentBarrierWarning` is replaced by a build-blocking
`DivergentThreadgroupBarrier` when safety cannot be proven.

Acceptance:
* producer/barrier/consumer shared-memory fixture is deterministic;
* divergent branch and early-return fixtures fail at `__syncthreads()`;
* barrier-free Stage 1-7 kernels remain unchanged.

## 11. MILESTONE 8F - RUNTIME MEMORY OPERATIONS
Implement and validate:
* synchronous `cudaMemset` for registered device ranges;
* host-to-device, device-to-host, device-to-device, and supported host-to-host
  `cudaMemcpy` forms with offsets and exact bounds;
* zero-byte operations and CUDA-compatible null/range validation;
* error propagation through `cudaGetLastError` and diagnostic mode.

Unified memory permits CPU memcpy/memset for synchronous shared buffers, but API
semantics and bounds remain CUDA-compatible. Performance implementation details
must not weaken validation.

Acceptance:
* full, partial, and offset memset/copy fixtures match independent host buffers;
* overlapping unsupported copies, out-of-range pointers, and invalid kinds fail;
* repeated allocation/copy/free tests preserve Stage 7 latency and lifetime gates.

## 12. MILESTONE 8G - MERKLE/NONCE COMPATIBILITY GATE
Add a repository-owned fixture derived from the required interfaces, with:
* project headers defining BYTE, WORD, SHA256_CTX, and expression macros;
* SHA helpers split across source/header boundaries;
* transaction hashing and odd-node Merkle reduction;
* grid-stride nonce search with `atomicMin`;
* an independent CPU oracle for hashes, Merkle roots, and smallest nonce;
* direct `mcu compile`, separate `-dc`/link, and `mcu make` paths.

Stage 8 does not depend on the user's external assignment directory in CI. The
external project is rerun manually as a compatibility probe, while stable test
fixtures live in this repository.

Acceptance:
* helper SHA vectors match exactly;
* Merkle roots match the CPU oracle for 1, 2, 3, 7, and larger transaction counts;
* nonce search returns the smallest valid nonce over fixed deterministic ranges;
* repeated runs are deterministic;
* generated MSL compiles with no remaining source CUDA symbols;
* the external assignment source set compiles without source modifications.

Full assignment CLI/file-output equivalence remains the Stage 9 exit gate.

## 13. ROUTING SCHEMA
Routing schema version 1 may be extended only with backward-compatible optional
fields during Stage 8. Dynamic threadgroup descriptors include a descriptor
version. Runtime behavior is:
* absent descriptors mean no dynamic threadgroup memory;
* unknown descriptor versions fail before dispatch;
* static compiler-only shared arrays do not create runtime descriptors;
* atomic metadata remains compiler-facing unless runtime configuration is needed.

A routing schema version 2 migration is still reserved for Stage 11 library
adapters unless Stage 8 proves an incompatible runtime change unavoidable.

## 14. REQUIRED DIAGNOSTICS
At minimum:
* `InvalidArrayParameterDecay`;
* `IncompleteDeviceCallGraph` and `UnresolvedDeviceCall`;
* `IllegalAddressSpaceCast` and `AmbiguousAddressSpace`;
* `UnsupportedVariableLengthArray` and `UnsupportedDeviceMemset`;
* `UnsupportedAtomicOperation`, `UnsupportedAtomicType`, and
  `UnsupportedAtomicAddressSpace`;
* `InvalidAtomicNonAtomicAccess`;
* `InvalidSharedDeclaration`, `DynamicSharedSizeMissing`,
  `ThreadgroupMemoryLimitExceeded`;
* `DivergentThreadgroupBarrier` and `CoarseningSharedKernelUnsupported`;
* `InvalidMemsetRange` and `InvalidMemcpyRange`.

Every diagnostic includes original CUDA file/line/column, symbol, pass, canonical
type, and inferred address space where applicable.

## 16. PERFORMANCE BUDGET
Correctness gates and benchmarks remain separate.

Build budgets on the current fixture/machine:
* Stage 7 no-op p95 <= 0.20 s and observed wall target near 0.05 s;
* one changed Stage 8 translation unit p95 <= 1.50 s;
* clean Merkle/nonce fixture build p95 <= 5.00 s;
* Stage 1-7 fixture regressions <= 15% without an explained toolchain change.

Runtime reporting:
* cold process/device/pipeline initialization is separate from warmed GPU time;
* atomic counter, reduction, Merkle, and nonce report median and p95 over at least
  five warmed samples;
* the 20,000-thread atomic counter target is <= 10 ms warmed;
* report transactions/s, SHA operations/s, nonce candidates/s, launch geometry,
  threadgroup-memory bytes, submission time, GPU completion, and synchronization;
* no cross-device universal speedup is claimed.

## 17. IMPLEMENTATION ORDER

### 8A - Compiler correctness repairs
Array decay, call completeness, pointer casts, diagnostic severity, and `-l/-L`.

### 8B - Private arrays and byte operations
Compile-time extents, local/struct arrays, address-space byte views, device memset.

### 8C - Typed atomics
Atomic-use analysis, integer operations, atomic loads, nonce winner.

### 8D - Threadgroup memory
Static shared arrays, dynamic descriptors, runtime byte binding, coarsening guard.

### 8E - Barrier safety
Uniformity analysis and build-blocking divergent barrier diagnostics.

### 8F - Runtime memory operations
cudaMemset and complete validated synchronous copy subset.

### 8G - Integration and performance gate
Repository fixture, external project probe, full regression, benchmark report.

Each milestone must pass its focused tests plus all prior-stage regressions before
the next milestone changes shared compiler/runtime contracts.
